# Aether Sigil - asset contract (painted art drop-in)

Generated by `game/tests/write_asset_contract.gd` from `game/scripts/assets.gd` `contract_slots()`. Do not edit by hand: re-run it after data changes. Machine-readable twin: `game/art/asset_slots.json`.

**739 slots.** Every slot already has a fallback (generated placeholder or procedural drawing), so any subset can be delivered in any order and appears with **zero code changes**.

## Where files go and how they are found

`res://` is the `game/` folder. A slot id is a path without `.png`. For `portraits/kess_varrow` the resolver tries, first hit wins:

1. `game/art/ai/portraits/kess_varrow.png` (restored / upscaled painted art, shipped)
2. `game/art/ai/from-concepts/portraits/kess_varrow.png` (crops of the owner's concept sheets)
3. `<repo>/art/ai/...` then `<repo>/art/ai/from-concepts/...` (the art agent's working folder, read directly in dev runs only; copy into `game/art/ai/` to ship)
4. `game/art/generated/png/...` (vector placeholders, see `art/generated/MANIFEST.md`)
5. bundled title art in `game/art/title/` (logo, key-art poster) for `ui/logo` and `backdrops/world` only
6. procedural drawing in code

**Ids must match these folders exactly** (category folder + id). Files in `game/art/ai/` need one `Godot --headless --path game --import` before an exported build sees them; dev runs and tests load un-imported PNGs raw.

### from-concepts naming the resolver already understands

Crops in `from-concepts/` may keep their sheet-style names; they are indexed by a normalised key:

| file | is used as |

| `champions/c01_lyra_quill.png` | `portraits/lyra_quill` |
| `protagonist/summoner_closeup.png` | `portraits/elio` (the protagonist) |

| `key-art/key_art_poster.png` | `backdrops/world` |
| `logo/logo.png` | `ui/logo` |

Canonical ids (the tables below) always work too and win over sheet-style names.
